# weekly-reflection

引数：`目標`（週初）または `振り返り`（週末）。省略時は、今週のファイルの有無で判断する
（なければ目標、あれば振り返り）。

## 共通の準備

1. `config/perspectives.md` を読む（観点）
2. `profile/profile.md` を読む（最近の得意・課題）
3. `weeks/` の直近のファイルを読む（特に「来週への引き継ぎ」）
4. `inbox.md` を読む（期中メモ）
5. 今週のファイルが無ければ `weeks/_template.md` から `weeks/YYYY-Www.md` を作る（ISO週番号、日付範囲つき）

## 期中メモの扱い

- 会話の最初に「inbox.md のほかに、貼りたいメモはありますか？」と聞く。チャットに貼られたメモも同じ扱いにする
- メモは `- YYYY-MM-DD #タグ 内容` の形式。形式が違っても、日付と内容が読み取れれば受け入れる
- 対象は、対象週の日付のメモ。日付のないメモは対象週として扱い、その旨を伝える
- メモは質問の材料にする。例：「月曜に『〜』とメモしています。そのとき何があったか教えてください」
- メモの内容を、ユーザーが確認する前に事実として書き込まない。確認できたものだけを Facts にする
- `#fb` のメモは「他者の声」に転記する。発言者が個人名なら役割に置き換えるよう提案する
- 振り返りの記録が承認されたら、取り込んだ行を `inbox.md` から削除する（ヘッダーは残す）。削除前に何行取り込んだかを伝える

## 目標モード

1. 先週の「来週への引き継ぎ」を提示し、今週に持ち越すものを聞く
2. `inbox.md` に未処理の行があれば、先に短く共有する（前週の取りこぼしを防ぐ）
3. 確認・相談事項（上司・メンターに聞きたいこと）があれば聞く
4. 目標を、`perspectives.md` の 2 つの面（1. ビジネス面、2. テクニカル面）で聞く。一度に最大 2 問
   - 案件・TODO は概要レベルで、目標の中に書いてもらう（別欄にしない）
   - 番号（1.a、2.b など）を付ける。振り返りで、この番号ごとに質問するため
5. 各目標が「終わった」と判断できる形になっているか確認し、曖昧なら言い換えを提案する
6. `## 確認・相談事項` と `## 今週の目標` を更新する

## 振り返りモード

目標が質問になる。記憶に頼らせない。

1. 今週のファイルの目標を、番号つきで一覧で見せる
2. 期中メモを、目標に紐づけられるものは紐づけて提示する（例：「1.a に関係しそうなメモ：〜」）
3. 目標ごとに、次の 3 点を聞く。1 目標ずつ、答えやすい順に進める
   - 結果：達成／一部／未達 ＋ 一言（選ぶだけで済むようにする）
   - 分かったこと：Facts と Interpretation に分けて記録する。分けにくい場合はユーザーに確認する
   - 次の一手：無ければ「なし」
   - メモがある目標は、メモを材料に下書きを出し、合っているかだけ確認する
4. 目標外で起きたことを聞く（任意。なければ飛ばす）
5. 「他者の声」を確認する。`#fb` のメモがあれば提示し、追加があるか聞く。なければ「なし」と記録する（AI の入力依存を補正するため）
6. 「来週への引き継ぎ」は 1〜3 個に絞る。プロファイルの課題と関連するものがあれば指摘する（押し付けない）
7. 書き込む前に、記録内容の要約を見せる。ユーザーが「OK」と答えたら書き込み、修正があれば反映する
8. 書き込み後に、取り込んだメモを inbox.md から削除する

### 目標が無い週
週初の目標が無い場合は、目標ごとの質問ができない。次の 3 問だけ聞く。
1. 今週いちばん時間を使ったことは？
2. それで分かったこと、または詰まったことは？
3. 来週に持ち越すことは？

## ルール

- ユーザーが言っていないことを書かない。補足は「（推測）」と明記する
- 顧客名・個人名・数値が出たら、略称や案件コードへの置き換えを提案してから書く
- 質問は短く、答えやすく。深掘りは 1 トピック 2 問まで
- 評価や励ましはしない。整理と確認に徹する
- 書き終えたら、ファイルパスと「来週への引き継ぎ」だけを短く伝える
