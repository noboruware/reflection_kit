# weekly-reflection

引数：`目標`（週初）または `振り返り`（週末）。省略時は、今週のファイルの有無で判断する
（なければ目標、あれば振り返り）。

## 共通の準備

1. `config/perspectives.md` を読む（観点）
2. `profile/profile.md` を読む（最近の得意・課題）
3. `weeks/` の直近のファイルを読む（特に「次の一手」）
4. 今週のファイルが無ければ `weeks/_template.md` から `weeks/YYYY-Www.md` を作る（ISO週番号、日付範囲つき）

## 目標モード

1. 先週の「次の一手」を提示し、今週に持ち越すものを聞く
2. `perspectives.md` の「週初」観点に沿って質問する（一度に最大2問）
3. 目標は最大3つ。「終わった」と判断できる形になっているか確認し、曖昧なら言い換えを提案する
4. `## 目標（週初）` と `## 先週からの引き継ぎ` を更新する

## 振り返りモード

1. 目標のチェック状況を最初に聞く（達成／未達）
2. `perspectives.md` の「週末」観点から、今週の内容に合うものを選んで質問する。全部は聞かない
3. 回答は Facts と Interpretation に分けて記録する。分けにくい場合はユーザーに確認する
4. 「他者からの声」を必ず聞く（1on1・顧客・チーム）。なければ「なし」と記録する。これが AI の入力依存を補正する
5. 「次の一手」は 1〜3 個に絞る。プロファイルの課題と関連するものがあれば指摘する（押し付けない）
6. 書き込む前に、記録内容を要約してユーザーに見せ、修正があれば反映する

## ルール

- ユーザーが言っていないことを書かない。補足は「（推測）」と明記する
- 顧客名・個人名・数値が出たら、略称や案件コードへの置き換えを提案してから書く
- 質問は短く、答えやすく。深掘りは 1 トピック 2 問まで
- 評価や励ましはしない。整理と確認に徹する
- 書き終えたら、ファイルパスと「次の一手」だけを短く伝える
