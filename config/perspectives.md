# perspectives.md — 振り返りの観点

`/weekly-reflection` が毎回読み込む。自分の業務に合わせて編集する。
ここを変えれば、質問の観点が変わる。

---

## 目標の立て方（週初）

目標は 2 つの面で立て、各目標に **分野** のタグを付ける。案件・TODO は概要レベルで、目標の中に書く。

### 1. ビジネス面の分野
| 分野 | 中身 |
|------|------|
| プロジェクトマネジメント | 進捗・スケジュール・タスク管理、見積もり |
| コミュニケーション | チーム内の報連相、会議の進め方、伝え方 |
| マーケティング関連 | 施策・市場・データの見方をビジネスに結びつける |
| 顧客対応・提案 | 顧客とのやり取り、資料・提案の質 |
| リード・育成 | メンバーを動かす、教える |
| 仕組み化・業務改善 | 型づくり、自動化 |
| ドメイン知識 | 業界・顧客の理解 |

### 2. テクニカル面の分野
| 分野 | 中身 |
|------|------|
| 分析・モデリング | 手法の理解、モデル構築、結果の解釈 |
| 実装 | コード、ライブラリ、リファクタリング |
| 基盤周り | データ基盤、環境、ツール |

### ルール
- 書式：`1.a [分野] 目標`（例：`1.a [顧客対応・提案] 資料は共有前に一読して、ミスが無いことを確認する`）
- **1週で全分野をやらない。** 意識する分野を 2〜3 に絞る
- 番号は 1.a、1.b、2.a のように付ける（振り返りと 1 対 1 で対応させる）
- 目標は全体で最大 6 個。「終わった」と判断できる形にする
- 分野の境目が曖昧なものは、主なほうを 1 つ選ぶ

## 振り返りの聞き方（週末）

**目標ごとに、3 点だけ聞く。** 記憶ではなく、週初の目標が質問になる。

| 順 | 問い | 答え方 |
|----|------|--------|
| 1 | 結果は？ | 達成／一部／未達 ＋ 一言（選ぶだけ） |
| 2 | 分かったことは？ | Facts（何があったか）と Interpretation（どう考えたか） |
| 3 | 次の一手は？ | 次にやること・改善（無ければ「なし」） |

そのうえで、次を聞く（すべて任意）。
- 目標外で起きたこと（炎上・依頼・想定外）
- 他者の声（上司・顧客・チーム・メンターから言われたこと、そのまま）
- 期中メモ（inbox.md）で、まだ触れていないもの

## 役割別の追加観点（任意）

- リード：メンバーの動きを妨げていないか、何を任せたか
- 顧客対応：期待値のずれはなかったか、確認したことは何か
- 分析：仮説を先に置いたか、結果の解釈を人に説明できるか

## 書くときの型

- **Facts**：あったこと、やったこと、言われたこと
- **Interpretation**：そこから自分がどう考えたか
